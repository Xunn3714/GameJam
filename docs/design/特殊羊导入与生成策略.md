# 特殊羊导入与生成策略

- **状态**：Accepted（已实现并完成 Unity EditMode 验证）
- **适用场景**：`Assets/_Game/Scenes/AlphaFlockExpansion.unity`
- **最后更新**：2026-09-05
- **上游玩法**：[羊群暴力扩张 Alpha](羊群暴力扩张Alpha.md)
- **维护要求**：特殊羊的目录、概率、生成规则或图鉴字段发生变化时，必须同步更新本文档。

## 1. 目标

特殊羊使用一套数据源完成素材登记、刷新、类型查询、统计和图鉴展示。美术成员以后只需把新的 PNG 放入对应品质文件夹，新羊即可被自动登记；不需要手工创建 Prefab，也不需要同时维护 Excel、刷新表和图鉴表。

当前阶段接入特殊羊的外观、品质、刷新、统计和图鉴文本；紫色和金色羊额外接入统一的获得发光与移动拖尾，金色羊还有常驻环绕粒子。绿色、蓝色和彩蛋羊不播放品质特效。表格中其他尚未实现的粒子、能力、解锁条件和结局影响只作为说明保存，不直接产生玩法效果。

## 2. 唯一配置

实现目标是让运行时与编辑器共同使用一个 `SpecialSheepCatalog` ScriptableObject。完成后，当前主流程中的 `ProgressiveSheepSpawner`、类型显示、统计和图鉴都读取该资产，不再各自保存特殊羊列表。

当前资产路径为 `Assets/_Game/Content/Data/Sheep/SpecialSheepCatalog.asset`。策划在这里调整各品质文件夹的绝对概率、羊种是否允许刷新和图鉴文本；基础可招募羊 Prefab 也由这份资产统一引用。

配置至少包含：

| 字段 | 含义 |
|---|---|
| 普通羊 Prefab | 所有普通羊和特殊羊实例共用的基础可招募 Prefab |
| 特殊羊根目录 | 包含各品质子文件夹的美术目录 |
| 品质文件夹 | 绿色、蓝色、紫色、金色和彩蛋对应的文件夹 |
| 品质概率 | 每次生成一组羊时命中该品质的绝对概率 |
| 羊种条目 | 编辑器根据文件夹内的 PNG 自动登记的羊种列表 |

当前默认概率：

| 文件夹 | 品质 | 每组命中概率 |
|---|---|---:|
| `绿色羊` | Green | 20% |
| `蓝色羊` | Blue | 5% |
| `紫色羊` | Purple | 1% |
| `金色羊` | Gold | 0.3% |
| `彩色羊` | EasterEgg | 0.1% |
| 未命中 | Common | 73.6% |

品质概率是绝对概率，不因文件夹中羊种数量变化而改变。所有特殊品质概率之和不得超过 100%，剩余概率自动归入普通羊。

## 3. 文件夹与自动登记

编辑器只扫描 `Assets/SpecialSheep` 下各品质文件夹的**直接子文件 PNG**：

```text
Assets/SpecialSheep/
├─ 绿色羊/
├─ 蓝色羊/
├─ 紫色羊/
├─ 金色羊/
└─ 彩色羊/
```

规则：

- PNG 所在文件夹决定品质；Excel 工作表和图片颜色不决定品质。
- 文件名默认作为图鉴显示名。例如 `草羊.png` 位于 `绿色羊`，则它是绿色品质的“草羊”。
- 新 PNG 导入后自动加入目录，无需手工修改刷新器或创建 Prefab。
- 品质目录保持单层结构，不在羊种下面再放同名附属文件夹；任何意外出现的嵌套 PNG 都不会登记为羊种。
- 每个羊种使用 Sprite 资源 GUID 建立稳定类型 ID。重命名或在 Unity Project 窗口中移动资源时保留 `.meta`，类型 ID 不变。
- PNG 在品质文件夹之间移动后更新品质，但不改变类型 ID。
- PNG 重命名后，未手工定制过的显示名和默认占位描述会自动跟随文件名更新；已经定制的图鉴文本保持不变。
- PNG 被删除或引用丢失时，保留目录记录并标记为不可刷新，同时在 Inspector 显示错误，避免旧统计或未来存档失去类型引用。
- 自动同步结果按稳定键排序；没有实际变化时不得反复改写资产，避免产生无意义 Git diff。

新图片的默认图鉴文案可以由文件名生成。需要更完整的文案时直接编辑同一目录条目，不再维护第二份运行时表。

日常添加流程：把主图 PNG 直接放到目标品质文件夹，等待 Unity 导入完成，然后只在需要补文案或禁用刷新时打开 `SpecialSheepCatalog.asset` 编辑对应条目。移动或重命名已有羊时应在 Unity Project 窗口操作并连同 `.meta` 保留，避免它被识别成一个全新的羊种。

首次导入可以从 `特殊羊羊图鉴.xlsx` 迁移名称、特效说明、效果说明、备注和地区。迁移完成后，Excel 只作为原始策划资料，不参与运行时，也不决定品质和概率。

## 4. 羊种条目

每个自动登记条目至少保存：

| 字段 | 规则 |
|---|---|
| `typeId` | 由资源 GUID 生成或沿用已有稳定 ID；不包含品质 |
| `displayName` | 首次登记时使用 PNG 文件名 |
| `quality` | 来自所在品质文件夹 |
| `sprite` | 对应的主图 Sprite |
| `codexDescription` | 图鉴短描述；缺省时使用统一占位文案 |
| `visualEffectDescription` | 策划描述，当前不自动创建实际特效 |
| `gameplayEffectDescription` | 策划描述，当前不自动创建实际能力 |
| `unlockHint` | 可选的出现条件或收集提示 |
| `spawnEnabled` | 素材和配置有效时为真 |

现有礼帽羊、蝴蝶结羊、山羊和黑色小羊应沿用已有类型 ID，避免破坏当前统计与引用。其他羊在首次登记时生成稳定 ID，此后不因改名或改变品质而变化。

## 5. 按组生成

特殊羊概率按“生成组”判定，不按组内每一只羊分别判定。

每次补充一组羊时执行：

1. 根据当前阶段确定组大小 `N`。
2. 对整组执行一次品质判定。
3. 未命中特殊品质时，生成 `N` 只普通羊。
4. 命中特殊品质时，从该品质中选择一个本局处于“可用”状态的羊种。
5. 生成 `N` 只完全相同类型的特殊羊，并为它们登记同一个运行时组 ID。
6. 一个生成组内不得混合普通羊、不同特殊羊或不同品质。

示例：历史最高羊数处于 20～49 阶段，本次组大小为 6。品质判定命中蓝色并选中哭哭羊后，本组生成 6 只哭哭羊；不会生成 1 只哭哭羊加 5 只普通羊。

世界种子必须同时决定组大小、品质和具体羊种。同一个非零 `WorldSeed`、同一份目录和同样的游戏过程应得到可复现结果。

## 6. 单局唯一状态

“每种特殊羊单局只生成一次”按唯一特殊羊组解释：同一类型在一局中最多存在一个有效生成组，但该组可以包含多只相同羊。

每种特殊羊具有三个运行时状态：

| 状态 | 含义 | 能否被新组抽取 |
|---|---|---|
| Available | 本局尚未出现 | 可以 |
| Active | 唯一特殊羊组已生成，尚无人加入羊群 | 不可以 |
| Collected | 该组至少一只羊已被招募 | 本局永久不可以 |

状态转换：

```text
Available
  └─ 特殊羊组成功生成 → Active

Active
  ├─ 任意一只被招募 → Collected
  └─ 整组在无人被招募前由距离系统完全回收 → Available

Collected
  └─ 本局不再离开该状态
```

补充规则：

- `Active` 类型不得生成第二组，避免地图上同时出现重复特殊羊组。
- 一旦组内任意成员被招募，同组剩余成员仍可正常招募，但不会再生成新的同类型组。
- 羊种进入 `Collected` 后，即使成员随后被狼叼走、被打散或全部消失，也不会重新开放。
- 只有整个特殊羊组在没有任何成员被招募的情况下被距离系统完全回收，类型才返回 `Available`。这避免玩家从未见到的镜头外特殊羊永久绝版。
- 场景重新开始时清空所有状态。

## 7. 品质耗尽与失败回退

- 命中某品质但该品质没有 `Available` 且可刷新的羊种时，本组生成普通羊。
- 不重新抽取其他品质，不向低品质降级，也不按剩余品质重新归一化概率。
- 品质文件夹为空却配置了非零概率时，编辑器显示配置错误；进入运行时仍安全回退为普通羊。
- 特殊羊组只有在全部成员成功创建后才进入 `Active`。创建失败时清理残留实例并生成普通羊组。

红箱子的固定奖励只从彩色、紫色和金色品质中选择。系统先合并三档里本局可用且图鉴尚未发现的所有羊种，每只羊等概率，因此各品质概率按未发现候选数占比分配；如果三档都已发现，则退回三档全部本局可用羊种组成的等概率候选池。

## 8. 图鉴与统计

- 图鉴按 `typeId` 展示一种羊一次，不按组内个体数量重复创建条目。
- 本局首次招募该类型时触发一次图鉴发现事件。
- 当前构成、累计招募和被狼抓走仍按真实羊实例计数。例如招募 6 只哭哭羊，构成中记录 6，只解锁一个哭哭羊图鉴条目。
- 当前阶段不增加跨局图鉴存档；后续确认长期收集玩法后再建立窄范围存档。
- 未实现的特效和能力只显示策划说明，不参与生成器和羊群能力计算。

## 9. 集成边界

- 完成集成后，当前主流程只有 `SpecialSheepCatalog` 是特殊羊数据源。
- `ProgressiveSheepSpawner` 从目录读取品质概率和羊种，删除当前 Scene 中逐羊硬编码权重的维护方式。
- `AlphaRunStats`、结果页和未来图鉴通过 `typeId` 查询同一目录。
- `AlphaFlockExpansionSceneSetup` 只负责给刷新器绑定目录资产，不硬编码所有羊种。
- 归档 `Level_01` 的旧 `SpecialSheepPool` 可以保留兼容，但不参与当前主流程，也不要求继续维护。
- 复用现有 `RecruitableSheep`、`SheepIdentity`、`SceneLoader`、`AudioManager`、`PauseManager` 和 `AlphaFlockExpansion/GameCanvas`。
- 不新增 asmdef，不修改 `ProjectSettings/`，不直接手工编辑 Scene 或 Prefab YAML。

## 10. 验收标准

- 在任一品质文件夹直接添加一张有效 PNG 后，Unity 导入完成时目录自动出现对应羊种。
- 新羊无需专用 Prefab，即可在 Alpha 场景中生成、招募、跟随、统计并被图鉴查询。
- 每组只包含一个类型；特殊羊组内所有成员 Sprite 和 `typeId` 相同。
- 品质命中概率不随文件夹羊种数量变化。
- 同一特殊羊类型在 `Active` 或 `Collected` 状态下不会产生新组。
- 未被招募且整组回收的特殊羊可以在之后重新出现。
- 已招募类型即使全部损失也不会重新出现。
- 品质耗尽、空文件夹、缺失 Sprite 和概率配置错误均安全回退，不产生空引用或半组对象。
- 固定种子下的组大小、品质和羊种选择可复现。
- 现有主菜单、暂停、狼群、出口、统计和结算流程保持可用。
