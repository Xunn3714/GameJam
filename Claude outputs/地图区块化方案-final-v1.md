## 1. 总体结构

一张 240×140 的大地图，按 **3 列 × 2 行** 切成 6 个 **80×70** 的区块槽位，每局按世界种子（`WorldSeed` 第 4 路随机流）分配：

| 槽位 | 数量 | 规则 |
|---|---|---|
| 出生点 | 1 | 随机一格；教程羊圈、6 只教程羊、地面标识、羊群、初始羊、相机整体挪过去 |
| 宝塔 | 1 | 随机一格（与出生点不同），洪山宝通寺限定生成在格内 |
| 出口 | 1 | 随机一格 + 随机该格贴外圈的一条边；外围围栏只有这条边可撞开 |
| 随机槽 | 3 | 从 森林×2 / 平原×2 / 村庄×2 池里按权重抽，可重复；**保底至少 1 个村庄**（抽不到就把最后一格换成村庄） |
| 湖泊 | 0~2 | 类型枚举已预留，素材待美术确认后再加入池 |

通关规则不变：历史最高 ≥ 100 解锁出口 → 当前羊数 ≥ 100 时 E 冲刺撞开出口边围栏 → 羊群中心越过边界即胜利；0 只立即失败。

第一版全图仍用一张 `草原_背景` 草地贴图，区块靠道具和地标区分；分区块地面贴图放到后续美术 PR。

## 2. 区块内容

### 森林（2 份模板）
- 大树 / 石块密度高（约 3 个 / 100 平方单位），小草小花少量。
- 树木变体：`WorldDebrisSpawner.DebrisEntry[]` 本身就是列表，美术每交一种新树（完好 + 坏两张同画布），加一条 `DebrisSpec` 即可进入抽取，不需要改逻辑。
- 后续可选：20 只以下需要"挤一下"才能进林，20 只以上直接踏破（本次不做）。

### 平原（2 份模板）
- 平原·草：小草 / 小花 / 花丛为主，密度约 0.8 / 100。
- 平原·石：小石头 / 石块为主，密度约 0.8 / 100。
- 农田 2×2 / 2×3 组块只在平原格生成。

### 村庄（2 份模板，保底 ≥ 1）
- **必然生成 2~4 套房屋区块**（`CreateHouseCompound`：房屋 + 1~2 干草垛 + 0~3 木桶 + 一段 90° 羊圈围栏），位置限定在格内，用 `TryFindPositionRelaxed` 逐级放宽间距。
- 房屋随机二选一：**小房子**（现有 `房子.png`）或 **大房子**（新素材，见第 4 节尺寸分析）。
- 每套房屋区块旁 **1~2 台拖拉机**（新素材 `拖拉机 (1).png` / `拖拉机（坏）.png`），当作普通可破坏物（接触即碎，碎后换坏图沉到 Background）。
- **固定 3 个红箱子** 在村庄格内；剩余 `7 − 3 × 村庄数` 个在非村庄、非出生格随机撒，总数恒为 7。奖励预留逻辑不变。
- 散布物密度低（约 0.3 / 100），只放花草。

### 出生点 / 宝塔 / 出口
- 出生点：复用现有羊圈资产，格内不刷散布物和地标。
- 宝塔：`洪山宝通寺.png`，落位后 `ClearDebrisAround` 清周围杂物（现有逻辑）。塌陷图 `图层 99.png` 可作为撞塌后的坏图（见第 5 节）。
- 出口：地面标识用 `箭头.png` 指向出口边；围栏贴图旋转复用，4 个方向不需要新图。

## 3. 区块边界

| 类型 | 表现 | 判定 |
|---|---|---|
| 河流 | `草原_河.png` 平铺（横向边旋转 90°），沿相邻格共享边铺设，**留边长 30%~40% 的浅滩缺口** | Blocking 层 BoxCollider2D，无 `BreakableObstacle` → 走路挡、E 冲刺也挡，零新玩法代码 |
| 公路 | 路面贴图（待定：新画或沿用 city 水泥地）+ 触发器条 | 羊群踩上路且冷却结束 → 生成运羊卡车（`大运.png`）沿路轴驶过：碰到在群成员 `ScatteredSheep.Scatter`（可回收）；碰到已脱队散羊 `SheepCapture.Carry`（抓走，不可恢复）；减到 0 只走现有失败逻辑 |

缺口留 30%~40% 的原因：成员场半径 = `max(5.5, 3.5 + 1.2√羊数)`，100 只时约 15.5 单位，6~8 单位的缺口会让大群过河成批脱队。

## 4. 新素材尺寸与重叠分析（`Desktop/塌`）

所有新图画布都是 **2304×1728**，完好 / 坏两张同画布，换图天然对齐（和红箱子、房屋现在的做法一致）。按项目现行 **128 PPU** 导入：

| 素材 | 不透明区域（px） | 128 PPU 下（单位） | 现有对照 | 建议 |
|---|---|---|---|---|
| 大房子（完好） | 1649×952 | 12.9×7.4 | 小房子 `房子.png` 306×341 px → 2.4×2.7，×1.25 后约 3×3.3 | 缩放 **0.5**（约 6.4×3.7），碰撞盒约 5.6×2.6、偏移向下 |
| 大房子（坏） | 1630×1139 | 同画布 | — | 随完好图同缩放即可 |
| 大树（新变体） | 1758×1660 | 13.7×13 | 现有 `Obstacle_Tree` Scale 1.1、Clearance 4.5 | 缩放 **0.35**（约 4.8×4.5），SolidRadius 0.7、Clearance 6 |
| 大树-坏（倒地） | 2021×949 | 横向 15.8×7.4 | — | 沉 Background 无碰撞，倒地宽度不影响通行 |
| 拖拉机 | 479×334（512×384 画布） | 3.7×2.6 | 木桶约 1.6 | 缩放 **0.6**（约 2.2×1.6），Clearance 2.5 |

**重叠风险与处理：**

1. **房屋区块内部**：现有 `CreateFurnitureSlots` 的 8 个家具槽位在中心 ±3.6~3.8 单位，`houseColliderSize` 2.8×3，90° 围栏角点在 ±3.4/±3.2——这些数值是按小房子调的。大房子宽 6.4 单位，会直接压住家具槽和围栏。处理：把槽位半径和围栏角点改成**按房屋碰撞盒半宽 + 边距**推导（大房子约 ±5.5），拖拉机也从同一批槽位里取，不新增槽位系统。
2. **房屋区块之间 / 与红箱子**：房屋区块找位置的 clearance 从 9 提到 **12**（大房子）；红箱子 clearance 6 不变；`TryFindPosition` 的 `OverlapCircle` 已经是全局物理查询，跨格不会叠。
3. **与散布物**：地标在散布物之后生成（order 30 > 0），房屋落位时 `OverlapCircle` 会避开已有花草，但家具槽位不检查散布物。处理：大房子落位后调用现有的 `ClearDebrisAround(position, 7f)`（宝塔已在用），把脚下杂物清掉。
4. **格子容量**：80×70 放 4 套大房子区块（每套约 13×13 含家具）+ 3 个红箱子 + 拖拉机是可以的，但会明显拥挤；建议**大房子 + 4 套** 时由 `TryFindPositionRelaxed` 兜底，或村庄模板 B 限定 2~3 套、模板 A 允许 4 套，两份模板正好做出松 / 紧两种手感。
5. **绘制顺序**：大房子高 3.7 单位，羊从房子"后面"走过会被遮住；现有房屋 sortingOrder = 2、羊在 Default 层，问题和小房子一样，只是面积更大。若想更自然，可给建筑加 `spriteSortPoint = Pivot` 并把 pivot 放在贴图底边（导入设置，不改代码）。

**命名提醒**：`大房子.png` 实际是塌掉的那张，`大房子-坏.png` 才是完好的，两张文件名反了；导入前让美术改回来，否则 `LoadBuildingSprite("大房子")` 会把废墟当完好图。

## 8. 每个 PR 的审核清单

1. **范围**：文件列表只含表中所列 + 对应 `.meta` + 重新生成的场景 / 资产；不得出现资产移动、`ProjectSettings/`、字体、其他场景。
2. **代码**：执行顺序（builder 的 `-100` Awake 早于所有 Start）；随机流编号不撞；固定角色互斥；`ClearManagedObjects` 名单同步。
3. **本地验证**：`Validate-UnityProject.ps1 -RunTests` 零错误全绿 → `Setup Scene` 跑两次不重复 → Gizmo 核对格子 → Play 3 局（种子 0）+ 固定种子 2 局复现。
4. **场景 diff**：只确认新增对象存在、无 missing guid、老对象没被删。
5. **PR 描述**：完成内容 / 改动资产 / 验证方式 / 已知风险（狼生成暂不夹边界、分区块地面未做）。
